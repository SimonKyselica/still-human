Denný gameloop — fázy A→B→C a modulárny task systém

Ako do projektu doplniť kompletný cyklus jedného dňa: štart pri posteli → poradie úloh (najedz sa → terminál → telefón → spánok) → prechod na ďalší deň. Vrátane fázového prepínania, signálu na rozozvučanie telefónu a jednoduchého UI. Tento dokument je len návod — žiadny súbor v projekte nebol zmenený, kód si vkladáš sám podľa krokov nižšie.

§Cieľ & výsledný loop

Chceš uzavretý cyklus dňa, kde sa úlohy plnia presne v danom poradí a systém je modulárny (pridanie úlohy = jeden riadok). Fázy z GDD:

Fáza A · Telefón Fáza B · Terminál Fáza C · Spánok + chores (najedenie, …)

Konkrétny deň, ktorý postavíme (poradie je dátové, takže sa mení jedným riadkom):

  1. Štart pri posteli — pri každom spustení hry hráč stojí pri posteli.
  2. Najedz sa — chore, interakcia s objektom jedla.
  3. Terminál (Fáza B) — odídeš k PC, spracuješ zmenu, vrátiš sa.
  4. Telefón zazvoní (Fáza A) — po dokončení terminálu signál rozozvučí telefón; zdvihneš ho.
  5. Spánok (Fáza C) — ľahneš si → deň +1 → reset úloh → opäť pri posteli.
Poznámka k poradiu telefónu. GDD opisuje telefón ako ranný rituál (Fáza A na začiatku). Ty si žiadal, aby telefón zazvonil po termináli (koncová zmena). Postavíme to teda takto — a keďže poradie je len pole v GameState, presunúť telefón na začiatok dňa je otázka prehodenia jedného riadku. Systém je na poradí nezávislý.

Relevantné časti projektu, na ktoré nadviažeme:

!Kľúčový problém, ktorý určuje celý dizajn

Zmena scény zničí Main. Keď PC spustí change_scene_to_file(AuditTerminal), celá izba — hráč, telefón, posteľ, akýkoľvek nód, ktorý by držal stav dňa — sa uvoľní z pamäte. Signál vyslaný v termináli teda nemá kto v izbe zachytiť, lebo izba neexistuje.

Dôsledok pre návrh:

  • Stav dňa musí žiť v autoloade (GameState), ktorý prežije zmenu scény. On je „model“.
  • V izbe je DayManager (radič), ktorý sa pri každom načítaní Main znovu zosynchronizuje z GameState — nedrží nič vlastné.
  • Preto „telefón zazvoní po termináli“ funguje takto: terminál zapíše dokončenie do GameState → vráti sa do Main → DayManager._ready() uvidí, že aktívna úloha je phone → rozozvučí telefón. To je robustný „signál naprieč scénami“.
Toto presne sedí na opakovaný vzor v projekte: chyby nebývajú v nastavení objektov, ale v nezapojenom vstupe / krehkej scéne. Preto stav zámerne držíme mimo scény.

Jedna úloha = jeden malý Resource. Vďaka tomu je systém modulárny a neskôr sa dá deň autorovať ako .tres (rovnako ako UnitCase v termináli). Fáza mapuje na GDD.

2GameState — poradie, index, fázy, signály

Sem pridáš celý „mozog“ dňa. Poradie úloh je jediné miesto, kde definuješ gameloop — pridať/prehodiť úlohu znamená upraviť _build_schedule(). complete_task() ignoruje všetko okrem aktívnej úlohy — to je vynútenie poradia.

Global Scripts/GameState.gduprav (nahraď obsah)
extends Node

# ── Príbehový stav (pôvodné, nezmenené) ──
var day: int = 1
var path: String = ""            # "A" / "B", nastaví sa v Deň 2
var vent_blocked: bool = false
var terminal_log: Array = []

# ── Kotva spawnu hráča: "BED" / "PC" / "PHONE" / "DOOR" ──
# Default "BED" → každé čerstvé spustenie začne pri posteli.
var last_player_pos: String = "BED"

# ── Denný task systém (gameloop) ──
var schedule: Array[DayTask] = []
var current_task_index: int = 0

signal task_advanced(new_task: DayTask)   # zmenila sa aktívna úloha
signal phase_changed(new_phase: String)   # zmenila sa fáza A/B/C
signal day_started(d: int)
signal day_completed(d: int)

func _ready() -> void:
	start_day(day)

# Zostaví poradie úloh pre daný deň — JEDINÉ miesto, kde žije gameloop dňa.
func start_day(d: int) -> void:
	current_task_index = 0
	schedule = _build_schedule(d)
	day_started.emit(d)

func _build_schedule(d: int) -> Array[DayTask]:
	var list: Array[DayTask] = []
	# Poradie = poradie v hre. Pridaj/prehoď riadok a máš iný deň.
	list.append(_task("eat",      "Najedz sa",                  "CHORE"))
	list.append(_task("terminal", "Dokonči zmenu na termináli", "TERMINAL"))
	list.append(_task("phone",    "Zdvihni telefón",           "PHONE"))
	list.append(_task("sleep",    "Choď spať",                 "SLEEP"))
	# Pre iný deň: if d == 2: ... (napr. pridaj úlohu s ventiláciou)
	return list

func _task(id: String, title: String, phase: String) -> DayTask:
	var t := DayTask.new()
	t.id = id
	t.title = title
	t.phase = phase
	return t

func current_task() -> DayTask:
	if current_task_index < 0 or current_task_index >= schedule.size():
		return null
	return schedule[current_task_index]

func current_task_id() -> String:
	var t := current_task()
	return t.id if t else ""

func current_phase() -> String:
	var t := current_task()
	return t.phase if t else ""

# Objekt zavolá, keď svoju úlohu dokončí. Ak to NIE je aktívna úloha, ignoruje sa
# → toto vynucuje presné poradie.
func complete_task(task_id: String) -> void:
	var t := current_task()
	if t == null or t.id != task_id:
		push_warning("complete_task(%s) ignorované — aktívna je %s" % [task_id, current_task_id()])
		return
	var prev_phase := t.phase
	current_task_index += 1
	var nxt := current_task()
	task_advanced.emit(nxt)
	if nxt == null:
		day_completed.emit(day)
	elif nxt.phase != prev_phase:
		phase_changed.emit(nxt.phase)

# Volá posteľ na konci dňa (úloha SLEEP).
func end_day() -> void:
	day_completed.emit(day)
	advance_day()
	start_day(day)
	last_player_pos = "BED"

# ── pôvodné metódy (nezmenené) ──
func log_decision(candidate_id: String, decision: String, flagged_correctly: bool) -> void:
	terminal_log.append({
		"candidate_id": candidate_id,
		"decision": decision,
		"flagged_correctly": flagged_correctly
	})

func advance_day() -> void:
	day += 1

func choose_path(chosen: String) -> void:
	path = chosen
	vent_blocked = (chosen == "A")
Prečo complete_task kontroluje id? Aj keby sa nejaký objekt omylom dal aktivovať mimo poradia, dokončenie sa zahodí. Poradie je tak vynútené na dvoch miestach: zamknutím interakcie (krok 3) aj tu.

3Zamykanie objektov podľa aktívnej úlohy

Do bázovej Interactable pridáš task_id a rozšíriš can_interact(). Keďže interaction_component ukáže prompt len ak can_interact()==true, zamknuté úlohy sa hráčovi ani nezobrazia. Pridáme aj hook on_became_active() (preň telefón zvoní).

Interactibles/interactible.gduprav (nahraď obsah)
class_name Interactable
extends StaticBody3D

@export var prompt_text: String = "Interact"
@export var enabled: bool = true

## Ak je vyplnené, objekt je interaktívny LEN keď je jeho úloha aktívna v GameState.
## Prázdne ("") = bežná rekvizita, vždy dostupná.
@export var task_id: String = ""

signal interacted(player: Node)

func can_interact() -> bool:
	if not enabled:
		return false
	if task_id != "" and GameState.current_task_id() != task_id:
		return false
	return true

func get_prompt_text() -> String:
	return prompt_text

func interact(player: Node) -> void:
	interacted.emit(player)

## Zavolá DayManager, keď sa úloha tohto objektu stane aktívnou.
## Prepíš v podtriede pre efekt (napr. telefón začne zvoniť).
func on_became_active() -> void:
	pass

4DayManager — radič v izbe

Nový nód v Main. Pri každom načítaní izby: spawne hráča na správne miesto, zapne len objekt aktívnej úlohy, rozozvučí telefón ak treba a postaví UI. Nedrží žiadny vlastný stav — číta z GameState. Objekty úloh nájde cez skupinu "task_objects".

Global Scripts/day_manager.gdnový súbor
class_name DayManager
extends Node

## Žije v Main.tscn. Pri každom načítaní Main sa znovu zosynchronizuje
## z GameState (perzistentný model), namiesto držania vlastného stavu.

@export var player_path: NodePath
var _player: Node3D
var _ui: VBoxContainer

func _ready() -> void:
	_player = get_node_or_null(player_path)
	if _player == null:
		_player = get_tree().current_scene.find_child("Player", true, false)
	_spawn_player()
	GameState.task_advanced.connect(_on_task_advanced)
	GameState.phase_changed.connect(_on_phase_changed)
	_sync_to_current_task()      # zapni správny objekt, rozozvuč telefón, postav UI

# ── Spawn hráča na pomenovanú kotvu ──
func _spawn_player() -> void:
	if _player == null:
		return
	var marker := _find_spawn(GameState.last_player_pos)
	if marker:
		_player.global_transform = marker.global_transform

func _find_spawn(anchor: String) -> Node3D:
	# Hľadá Marker3D s menom napr. "Spawn_BED".
	var n := get_tree().current_scene.find_child("Spawn_%s" % anchor, true, false)
	if n == null:
		push_warning("DayManager: chýba Marker3D 'Spawn_%s'" % anchor)
	return n as Node3D

# ── Synchronizácia scény s modelom ──
func _sync_to_current_task() -> void:
	var active := GameState.current_task_id()
	for obj in get_tree().get_nodes_in_group("task_objects"):
		if obj is Interactable:
			var it: Interactable = obj
			var is_active := it.task_id == active
			it.enabled = is_active
			if is_active:
				it.on_became_active()      # napr. telefón začne zvoniť
	_rebuild_ui()
	print("[DayManager] aktívna úloha = ", active, "  fáza = ", GameState.current_phase())

func _on_task_advanced(_new_task: DayTask) -> void:
	_sync_to_current_task()

func _on_phase_changed(new_phase: String) -> void:
	print("[DayManager] FÁZA -> ", new_phase)
	# TODO: sem hoď vizuál/zvuk fázy (napr. zmena osvetlenia v Ceste A)

# ── Jednoduché UI: zoznam úloh (vytvorí sa v kóde, netreba editovať scénu) ──
func _rebuild_ui() -> void:
	if _ui == null:
		var layer := CanvasLayer.new()
		add_child(layer)
		_ui = VBoxContainer.new()
		_ui.position = Vector2(40, 40)
		layer.add_child(_ui)
	for c in _ui.get_children():
		c.queue_free()
	for i in GameState.schedule.size():
		var t: DayTask = GameState.schedule[i]
		var row := Label.new()
		if i < GameState.current_task_index:
			row.text = "✔ " + t.title
			row.modulate = Color(0.44, 0.44, 0.39)   # hotové – tlmené
		elif i == GameState.current_task_index:
			row.text = "▸ " + t.title
			row.modulate = Color(0.88, 0.64, 0.22)   # aktívne – jantár
		else:
			row.text = "• " + t.title
			row.modulate = Color(0.35, 0.35, 0.32)   # zamknuté – šedé
		_ui.add_child(row)
Pripojenie na GameState signály sa robí v _ready. Keď sa Main uvoľní, DayManager zanikne a Godot spojenie automaticky odpojí — žiadny leak. Preto sa smie pripájať pri každom načítaní izby.

5Štart pri posteli — spawn kotvy

Spawn rieši DayManager._spawn_player(): prečíta GameState.last_player_pos a teleportne hráča na zhodný Marker3D. Stačí do Main.tscn pridať pomenované markery.

last_player_posMarker3D v MainUmiestni

"PC"Spawn_PCpri stoličke/stole
"PHONE"Spawn_PHONE(voliteľné) pri telefóne
"DOOR"Spawn_DOOR(voliteľné, koniec Cesty A)
Prečo to stačí. GameState je autoload — pri každom spustení aplikácie sa vytvorí nanovo, takže last_player_pos je späť na "BED". Počas hry sa mení (napr. na "PC" pri odchode k terminálu), takže návrat z terminálu ťa vráti k stolu. Po spánku sa end_day() resetuje na "BED".

6Telefón — signál, ktorý ho po termináli rozozvučí

Telefón teraz štartuje vypnutý a tichý. Rozozvučí sa cez on_became_active(), ktorý zavolá DayManager vo chvíli, keď sa phone stane aktívnou úlohou — čo nastane po dokončení terminálu. Zvuk zvonenia doplníš neskôr na jednom mieste (start_ringing()).

8Jednoduché tasky — SimpleTask (najedenie a ďalšie)

Generický objekt na chores. Interakcia = dokončenie úlohy (plus voliteľný dialóg). Pridať novú úlohu „umy si zuby“ / „napi sa kávy“ znamená len položiť ďalší SimpleTask s iným task_id a pridať riadok do _build_schedule. To je tá modularita.

Interactibles/simple_task.gdnový súbor
## Generický jednorazový task: interakcia dokončí jeho úlohu.
## Polož do izby, nastav task_id + prompt_text v Inšpektore. Skupinu rieši _ready.
class_name SimpleTask
extends Interactable

@export var say_lines: Array[String] = []     # voliteľný flavour dialóg
@export var say_sfx: AudioStream                 # hlas pre say_lines (ak ich používaš)
@export var say_pos: Vector2 = Vector2(960, 900)

func _ready() -> void:
	add_to_group("task_objects")

func interact(player: Node) -> void:
	super.interact(player)
	if not say_lines.is_empty():
		DialogueManager.start_dialog(say_pos, say_lines, say_sfx)
	GameState.complete_task(task_id)

Pre úlohu „Najedz sa“: pridaj do izby ľubovoľný StaticBody3D na fyzickej vrstve 1 (napr. tanier na nočnom stolíku), priraď mu simple_task.gd, v Inšpektore nastav task_id = "eat" a prompt_text = "Eat breakfast". Hotovo — je súčasťou poradia.

9UI — zoznam úloh

Už je hotové v kroku 4 (DayManager._rebuild_ui()). Vytvorí si vlastný CanvasLayer + VBoxContainer, takže netreba editovať žiadnu scénu. Ukazuje:

  • ▸ aktívna úloha — jantárová,
  • ✔ hotová — tlmená,
  • • zamknutá — šedá.

Prestaví sa sám pri každom task_advanced aj pri načítaní izby. Neskôr štýl/pozíciu prepíšeš vlastnou scénou a priradíš ju namiesto auto-vytvoreného kontajnera.

Posteľ je poslednou úlohou (sleep), takže je odomknutá až keď je všetko ostatné hotové. Interakcia zavolá end_day() (deň +1, reset úloh, kotva "BED") a znovu načíta izbu — čerstvý deň, opäť pri posteli.

§Budúcnosť: ukladanie hry po dňoch

Loop je navrhnutý tak, že ukladanie je priamočiare — celý stav dňa je už v GameState. Pri spánku ulož, pri štarte načítaj. Ukladaj práve tieto polia:

Global Scripts/GameState.gd (náčrt, dorobíš neskôr)nice-to-have
const SAVE_PATH := "user://save.cfg"

func save_game() -> void:
	var cfg := ConfigFile.new()
	cfg.set_value("day", "day", day)
	cfg.set_value("day", "task_index", current_task_index)
	cfg.set_value("day", "last_player_pos", last_player_pos)
	cfg.set_value("story", "path", path)
	cfg.set_value("story", "vent_blocked", vent_blocked)
	cfg.save(SAVE_PATH)

func load_game() -> bool:
	var cfg := ConfigFile.new()
	if cfg.load(SAVE_PATH) != OK:
		return false
	day = cfg.get_value("day", "day", 1)
	start_day(day)
	current_task_index = cfg.get_value("day", "task_index", 0)
	last_player_pos = cfg.get_value("day", "last_player_pos", "BED")
	path = cfg.get_value("story", "path", "")
	vent_blocked = cfg.get_value("story", "vent_blocked", false)
	return true

Keďže sa ukladá „po dňoch“, najčistejšie je save_game() zavolať v end_day() (t.j. keď si ľahneš spať) a load_game() skúsiť v _ready() namiesto natvrdo start_day(1).
