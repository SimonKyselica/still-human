The loop, phase by phase

Phase A — Phone / Handler PARTIAL

GDD: player wakes to ringing; picking up is the only way forward; the Handler delivers that day's rules & atmosphere (Day 1 onboarding + sinister warning, Day 2 vent reassurance, Day 3 warning / thanks + "odzraví").

Built: phone rings when its task is active, pickup runs a dialogue and hangs up, lines branch clean/dirty (praise vs reproach).

  • MISSING Day-specific Handler scripts (D1 rules, D2 vent reassurance, D3 warn/deactivate) — pick lines by GameState.day and path, the same way the praise/reproach branch already does.
  • DECISION Ordering: the schedule is terminal → phone → sleep, so the phone is a post-shift call. The GDD's Phase A is a morning rules call. Either add a second, opening phone task in _build_schedule or accept the post-shift framing — decide before writing Handler content.

Phase B — Terminal PARTIAL

GDD: two panels (candidate folder + interview transcript), three verdicts CLEAR / HOLD / ESCALATE (= your APPROVE / HOLD / INCINERATE) plus FLAG to mark a contradiction between a folder field and a transcript claim. Day 2's rule contains a real contradiction; Path A glitches the screen.

Built: full folder + transcript + verdict + FLAG-compare, directive lines, per-day caseload loading, finish-shift → back to room.

  • MISSING Day-2 and Day-3 caseloads (Audit/cases/Day2/, Day3/). Only Day 1 (2 units) exists.
  • MISSING Day-2 contradictory directive — the first "real" decision, not a rule-lookup.
  • MISSING Path-A glitch overlay on the terminal (CRT scanline + flashing "WAKE UP" / "PRISONER").
  • FIX log_decision stores {candidateId, decision, flaggedCorrectly} but not whether the verdict was right. Day-3-A needs the Handler to name a specific mis-judged unit — store correctness so you can look one up.
  • CLEANUP UnitCase.correct_verdict still lists "FLAG" in its enum — vestigial (FLAG is a modifier, not a 4th verdict). Remove it.

Phase C — Sleep PARTIAL

GDD: lie down to end the day; what follows depends on path. Day-1→2 and (Path A) Day-2→3 carry dream sequences; the bed is the dream's carrier.

Built: bed fades the screen, plays a sound, calls GameState.end_day() (advances day + rebuilds schedule) and reloads the room. The day loop genuinely turns over.

  • MISSING Dream sequences (below) hooked into the sleep transition.
  • VERIFY bed.gd tweens a node in group "screen_fader" — confirm that ColorRect exists in the running scene, or the tween targets null and errors on sleep.

The big missing pillar — Day 2 branch

VENT object + block choice MISSING

This is the decision of the whole game, and nothing for it exists yet.

  • A vent Interactable that becomes active on Day 2 (white-smoke VFX, clearly highlighted so it can't be missed).
  • Interacting = block it → set GameState.vent_blocked = true and call GameState.choose_path("A"); not blocking by end of Day 2 → choose_path("B").
  • Right now choose_path() and vent_blocked exist in GameState but are never called or read anywhere — the fork is inert.

Suggested build order

GDD §9: finish Day 1 completely before writing a line of Day 2. A polished Day 1 is a shippable demo; three half-days are nothing.

  1. Close out the Day-1 vertical slice. Decide phone ordering (morning rules vs post-shift), write the Day-1 Handler script + Day-1 directive, confirm the screen_fader node exists so sleep doesn't error. Goal: wake → phone → terminal → sleep → wake Day 2, start to finish, polished.
  2. Build the VENT + the fork. Vent Interactable + smoke, wire choose_path("A"/"B") and vent_blocked. This is the spine of Day 2 — do it before any Path-A art.
  3. Path-A room state. One room, switchable light/material set: night + hell window + PC glitch + "You're making a mistake". Read GameState.path on room load.
  4. Dreams. Day-2 dream on Day-1 sleep; Day-3 dream (Path A) on Day-2 sleep. Hook into the bed transition.
  5. Day-2 & Day-3 terminal content. Day-2 contradictory directive + caseload, Day-3 hardest caseload; add correctness to terminal_log for the Day-3-A callback.
  6. Endings. Door gating + walk-through (End A); deactivate call + dissolve + laughter (End B). Wire the terminal-log callback (Handler names a mis-judged unit).
  7. Audio/atmosphere pass. Ring as recurring fear leitmotif, Path-A drone/hum, Ending-B screams + laughter, Day-1 foreshadowing (vent sticker / faint sweet smell).
Cheap wins already banked: the state machine, task scheduling, interaction, dialogue, terminal and the day-turnover loop all work — so the remaining work is mostly content (Handler scripts, caseloads, journal) plus the vent fork and the Path-A visual set. The two heaviest items are the degraded-room art and the endings' dissolve VFX; everything else reuses systems you already have.
